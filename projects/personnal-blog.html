01 / The idea

More than
a website.

A publishing website is only the visible layer. Behind every page, several services need to communicate, process requests and store information.


This project explores that infrastructure by separating the application into independent Docker containers. Each service has a specific responsibility, while all of them communicate through the same internal network.

03 / The services

One task.
One service.

The architecture follows a simple principle: separate responsibilities so that each component can focus on one part of the application.

01

NGINX

Handles incoming HTTPS traffic on port 443. Static resources can be served directly while PHP requests are passed to PHP-FPM through the Docker network.

02

PHP-FPM

Provides the PHP runtime required by WordPress. It listens on port 9000 inside the container network and processes PHP scripts.

03

WORDPRESS

Provides the publishing layer of the application. WordPress runs on PHP and uses the shared application files together with the database.

04

MARIADB

Stores the application's structured data. WordPress connects to MariaDB through the internal Docker network on port 3306.
